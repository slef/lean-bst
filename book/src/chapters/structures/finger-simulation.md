# Simulating fingers

The multi-finger model of [Chapter 9](fingers.html) keeps several persistent fingers in one tree. The pointer machine of [Chapter 6](pointer.html) has a single cursor that starts at the root for every request. To simulate a finger, the cursor must reach it in a constant number of steps, however deep the finger is in the tree that is being simulated. Demaine, Iacono, Langerman and Özkan (*Combining binary search trees*, 2013) do this by reshaping the tree around the fingers. The paths between them are stored compactly, so that every finger stays near the root. The library builds its own version of their construction, with explicit constants.

- [Section 29.1](bst-deques.html) defines the building blocks. A *BST deque* is a binary search tree whose minimum and maximum are at depth one, so that nodes can be pushed or popped at either end in amortized constant work. A *tendon* stores a long path of a tree as two such deques.
- [Section 29.2](finger-hands.html) assembles them into a *finger hand*, which keeps every finger a constant number of steps from the root for a fixed number of fingers, and simulates each finger instruction at an amortized cost that is constant for a fixed number of fingers.

With $k$ fingers the simulation costs at most $344 + 60(k+1)$ times the multi-finger cost, in a proof file outside the reading interface. The reading interface states the case of one finger, the lazy finger: the comparison of dynamic BSTs with static lazy-finger trees in [Chapter 14](lazy-finger-hierarchy.html). The combination of [Chapter 23](combination.html) uses the hand with two fingers.
